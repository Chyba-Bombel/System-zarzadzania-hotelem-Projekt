HOTEL MANAGER 1.0.2 — URUCHOMIENIE

1. BAZA: WYBIERZ JEDEN PLIK

Masz bazę zgodną z wersją 1.0.1:
- Poprawka 1.0.2 nie wymaga SQL. Przejdź do konfiguracji i startu.

Masz starszą bazę, której struktura wymaga aktualizacji:
- Zamknij wszystkie stanowiska i zrób kopię bazy.
- Jako administrator wykonaj CAŁY db/aktualizuj_baze.sql.
- Nie wybierasz aktualizacji według etapów i nie importujesz danych demo.

Nie masz jeszcze bazy projektu:
- Jako administrator wykonaj jednorazowo db/nowa_baza.sql.
- Pełna instalacja zawiera już wszystkie zmiany i przykładowe rekordy.

Dla innego schematu dostosuj nazwę bazy. Aktualizacja wymaga zmiany USE na początku;
w nowej instalacji zastąp nazwę w całym pliku. Szczegóły: db/README.md.
Standardowe istniejące konta hotel_app otrzymują prawa podczas aktualizacji.
Własne konto: jednorazowy pomocnik db/administracja/uprawnienia.sql.
Folder administracja nie jest kolejnym etapem aktualizacji.

2. KONFIGURACJA I START

Rozpakuj całą paczkę do NOWEGO folderu, żeby nie mieszać starych klas i plików SQL.
Konfiguracja Windows: %LOCALAPPDATA%\HotelManagerData\config\db.properties.
Stary db.properties jest importowany tylko raz, jeśli nie ma konfiguracji użytkownika.
Po migracji edytuj ustawienia przyciskiem przed logowaniem, a nie stary plik projektu.
Dane połączenia są danymi MySQL, nie loginem pracownika.
Nie publikuj swojej konfiguracji. Skrypty nie resetują istniejących haseł.

Windows x64: JDK 17+, java i javac w PATH. Uruchom uruchom_windows.bat.
Biblioteki JavaFX Windows i JDBC są w lib. Nie dokładaj innych wersji JAR.
Linux: JDK 17+, Maven i pulpit z GTK; z folderu pom.xml uruchom mvn javafx:run.
IntelliJ: otwórz pom.xml jako Maven, ustaw JDK i uruchom javafx:run.
Launcher uruchamia GUI, Main konsolę. Pełna instrukcja: README.md.

3. KONTA DEMONSTRACYJNE

Pracownicy: admin / Admin123! oraz recepcja / Recepcja123!.
Konto MySQL demo: hotel_app / HotelDemo2026!.
Jeśli wcześniej zmieniłeś hasło, użyj swojego aktualnego.
Nowe hasła pracowników muszą spełniać wymagania formularza.
Po 5 błędnych logowaniach konto jest blokowane na 5 minut w bazie.
Serwer poza loopback wymaga TLS VERIFY_IDENTITY z zaufanym certyfikatem.

4. OBSŁUGA

Goście: aktywni, archiwalni, wszyscy; archiwizacja i przywrócenie bez kasowania
rezerwacji. Aktywne pobyty blokują archiwizację. Nowa rezerwacja wymaga aktywnej
kartoteki. Konsola: 32 archiwizacja, 33 przywrócenie, 34 lista archiwum.

Rezerwacje: główny i dodatkowi goście, kalendarz, zmiana dat/pokoju, historia,
notatki, meldunek, anulowanie. Zmiana pokoju dotyczy całego pobytu.
Usługi: ilość dla całego pobytu; historyczne ceny, anulowanie i rozliczenie.
Zmiana dat nie przelicza ilości, dostawka nie zwiększa pojemności pokoju.
Konsola: 25 historia, 29 usługi, 30 wyszukiwanie, 31 katalog administratora.
Wyszukiwanie: nazwisko także dodatkowego gościa, pokój, status, daty i saldo.
Karta i raporty: HTML/CSV, druk/PDF przez przeglądarkę. Notatki pozostają wewnętrzne.
Wymeldowanie wymaga rozliczenia noclegów i usług. Zwroty przyjmuje administrator.

Po zmianach na innym stanowisku użyj Odśwież dane. Po błędzie sieci przed ponownym
zapisem sprawdź stan: serwer mógł już zatwierdzić operację.
Instrukcje funkcji: pliki Markdown w głównym folderze. Testy: TESTOWANIE.md.

5. INSTALATOR I AKTUALIZACJE 1.0.2

Zachowaj hotel.ico w folderze projektu. Na Windows uruchom buduj_instalator.ps1.
Dokładne polecenia i migracja: AKTUALIZACJA_1.0.2.md.
Linux: bash buduj_instalator_linux.sh tworzy DEB i kompletne archiwum ZIP.
Logi: %LOCALAPPDATA%\HotelManagerData\logs. Wersja i ścieżki: O programie.
Ta poprawka nie wymaga zmiany bazy zgodnej z poprzednią wersją.
Pierwsze przejście ze starego instalatora: zachowaj konfigurację PRZED
odinstalowaniem, potem zainstaluj nową wersję. Nie usuwaj bazy.
